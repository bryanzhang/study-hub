0. 一句话全貌

核心思想

在 AlphaEvolve 式的代码发现系统里，"下一步扩展哪些候选、并行开几个、何时停"这套探索策略通常是人手写死的。Dream-RSI 把探索策略写成可执行的 Python 代码，并发现：已经跑完的发现树本身就是一个免费的模拟器——在它上面"回放"任何新策略，只需按记录揭示结果，不需要再调用一次 coding agent。于是可以每轮在线跑一次真实发现 → 把树存入历史 → 让一个"策略开发 agent"在所有历史树上离线改写、评估策略 M 次 → 选回放得分最高的版本上线。这就是"在梦里（replay）自我改进，醒来（online）再部署"的递归循环。

2. 动机：探索策略是瓶颈

AlphaEvolve、OpenEvolve、ShinkaEvolve 一类系统由 LLM 不断提出 → 评测 → 精炼候选程序，大规模时动辄成千上万次"提案–评测"循环。论文认为，随着底层 coding agent 越来越强，真正决定成本与效果的是探索策略：

  • 精炼哪个候选？是继续深挖一条分支（exploit），还是开新根（explore）？
  • 一批并行开几个 worker？
  • 什么时候判定一条分支没救了、什么时候整体停止？

以往这些都是人工设计且在发现过程中固定的，不能从自身历史中学习，于是会持续把算力浪费在无效方向上。而直接在线优化探索策略有两个难点：

  1. 反馈延迟且昂贵：一个策略好不好，要看它在很多轮提案–评测后的效果，单次评估就是一次完整的发现 rollout。
  2. 元搜索空间巨大：可能需要尝试大量候选策略，每个都要跑一次长 rollout，成本不可承受。
关键洞察

"Completed discovery histories already provide such a simulator."——一棵跑完的发现树记录了每个节点被扩展后得到了什么分数。只要新策略选择的节点"在记录里"，就可以直接读出结果，而不必真的调用 LLM。这就把昂贵的在线策略评估变成了廉价的离线回放，类似 RL 里的 off-policy evaluation / 世界模型里的"在梦中训练"（Dream 一词即来源于此）。

3. 问题形式化

3.1 发现树（Discovery Tree）

  • 根节点 $r$：初始工作区（workspace）。
  • 每个非根节点 $v$ 是一次"生成–评测"尝试，有唯一父节点（尝试从父节点的工作区出发，继承其工作区）。
  • 节点 $v$ 存储：结果工作区快照、产物（artifact）、诊断信息、分数 $s_v$（越高越好）。

当前观测到的树记为 $\mathcal{T}$，可选节点集为根加所有叶子：

$$A(\mathcal{T}) = \{r\} \cup \operatorname{leaves}(\mathcal{T})$$

选根 = 开一条新分支；选叶 = 在该候选上继续精炼。设有 $W$ 个并行 worker，可行动作是一个批次 $C \subseteq A(\mathcal{T}),\ |C| \le W$。

3.2 探索策略 π

策略 $\pi$ 是可执行代码（附录 prompt 中是一个 Python 类 OptimalPolicy，含 solve(question, budget) 与 plan_grid 方法）。每个决策轮，它观察当前树，输出一个批次；返回空批次即终止。同一次 rollout 内策略代码固定不变。

这一"编排层（orchestration layer）"让探索变得显式、可编程，控制以下四件事，而底层 coding agent、评测器、执行接口完全不变：

控制维度含义
节点选择扩展哪些叶子、是否开新根
分支开新分支 vs 继续已有分支
批大小 / 并行度本轮同时跑多少个尝试（≤ W）
停止返回空批次

4. 方法：Dream-RSI

图 1（本报告绘制）：Dream-RSI 的外层递归——每轮一次真实在线发现 + 一次纯离线的策略进化。"Evolving Worlds" 指回放世界（历史树集合）随轮数不断增长。

4.1 在线 rollout

第 $t$ 轮，策略 $\pi_t$ 可以读历史 $\mathcal{H}_{t-1}$（仅作上下文，与新树隔离），从 $\mathcal{T}_t^0 = \{r\}$ 出发，最多跑 $K_1$ 轮：

  • 每轮选批次 $C_t^k \in A(\mathcal{T}_t^k, W)$，每个被选节点并行执行一次生成–评测，各产生一个子节点；
  • 转移是随机的：同一工作区出发，coding agent 可能给出不同结果；
  • 结束后 $\mathcal{H}_t = \mathcal{H}_{t-1} \cup \{\mathcal{T}_t\}$。

4.2 离线回放模拟器（"做梦"）

把每棵历史树 $\mathcal{T}_i$ 当作一个固定的"世界"。对策略–树对 $(m, i)$，从 $\{r\}$ 开始回放：

  • 选非根节点 $v$：揭示 $v$ 在记录中的唯一子节点（若存在）。
  • 选根 $r$：揭示 $r$ 的最早创建、尚未揭示的子节点 → 相当于开新分支。
  • 没有记录的后继：返回空，不产生新节点（模拟器无法"想象"未发生的事）。
  • 策略只能从已揭示的合法集合 $A(\mathcal{T}_i^{m,k})$ 中选，看不到未揭示节点的分数。
  • 终止：策略返回空批次 / 达到 $K_2$ 轮 / 所有记录节点都已揭示。记完成轮数为 $k^\star$。
理解要点

这里的设计很巧妙：在线树里每个非根节点恰好"被精炼一次"，所以每个节点至多一个子节点（链式精炼），根下面有多个子节点（多条分支）。回放时策略做的决策本质是"在这些已记录的链上，按什么顺序、走多深、开几条、何时停"——这正是探索策略要学的东西，而结果都可以从记录里查到。代价是：策略无法被评估在记录之外的行为（例如对同一节点精炼两次），这就是该模拟器的覆盖偏差。

4.3 回放目标函数

令 $N_i^m = |\mathcal{T}_i^{m,k^\star}| - 1$ 为揭示的非根节点数（即消耗的尝试数）：

$$V_i^m \;=\; \underbrace{\max_{v \in \mathcal{T}_i^{m,k^\star}} s_v}_{\text{发现质量}} \;-\; \underbrace{\beta_1 N_i^m}_{\text{执行成本}} \;+\; \underbrace{\beta_2 \frac{N_i^m}{\max\{1, k^\star\}}}_{\text{并行奖励}}$$
  • 质量：回放过程中揭示到的最好分数；
  • 成本：每次尝试罚 $\beta_1$ —— 鼓励"够了就停"；
  • 并行：平均每轮尝试数乘 $\beta_2$ —— 鼓励批处理而非串行（同样的尝试数，轮数越少墙钟时间越短）。

策略的总体评分是在所有历史树上的平均：$\bar V^m = \frac{1}{t}\sum_{i=1}^{t} V_i^m$。

注意

正文未给出 $\beta_1, \beta_2$ 的具体数值。附录 B.2 的策略开发 prompt 中实际优化的是 pareto.reward = pareto.auc − λ · parallel_penalty（扫描 β 后的 AUC 形式），与公式 (1) 思想一致但并不完全等同。代码中 β 网格默认为 {0, 0.25, 0.5, 0.75, 1}，λ = 0.05，详见第 10 节。

4.4 策略改进循环

  1. $\pi_t^0 = \pi_t$；
  2. 对 $m = 0,\dots,M-1$：在全部 $t$ 棵历史树上回放 $\pi_t^m$，得到 $\bar V^m$；
  3. 一个固定的 LLM 策略开发 agent 阅读回放轨迹、得分和以往修改反馈，改写代码得到 $\pi_t^{m+1}$；
  4. 选 $\pi_{t+1} = \pi_t^{m^\star}$，$m^\star \in \arg\max_m \bar V^m$。
弱单调性

因为候选集合包含当前策略 $\pi_t^0$，必有 $\bar V^{m^\star} \ge \bar V^0$：在固定的历史上，选出的策略不会比当前策略差。但这只是"历史上的选择性质"，不是在线改进的保证——论文没有给出形式化定理，也没有量化回放分与在线表现的相关性。

4.5 伪代码（据正文重构）

Input: 初始策略 π_1（人工 "parallel refining"），H_0 = ∅，K1, K2, M
for t = 1, 2, ...:
    # ---- 在线：真实调用 coding agent ----
    T_t = Rollout(π_t, context=H_{t-1}, max_rounds=K1)   # 随机转移
    H_t = H_{t-1} ∪ {T_t}

    # ---- 离线：仅回放，零 agent 调用 ----
    π^0 = π_t
    for m = 0 .. M-1:
        V[m] = mean_{i=1..t} Replay(π^m, T_i, max_rounds=K2)
        π^{m+1} = PolicyDevAgent.revise(π^m, traces, V[0..m])
    π_{t+1} = π^{argmax_m V[m]}

附录 B.2 对策略开发 agent 的约束值得注意：只能编辑一个策略文件；必须 prefix-only（只用已揭示信息）；禁止使用未揭示分数或硬编码 cell ID；trace 数据只能在轮与轮之间读，不能在 solve() 内部读——这些都是在防止策略"偷看答案"从而在回放中作弊。

4.6 手把手玩具例子：一轮"在线 → 做梦 → 选策略"

类比

Dream-RSI 的离线阶段本质上就是量化交易的回测：不会每想出一个交易策略就拿真钱去试，而是先在历史行情上回放，看它当时能赚多少。这里的"历史行情"就是之前真实跑过的发现树。下面例子中的数字都是编的，只为说明机制。

先认识三个概念

概念含义
精炼（refine）选中一个已有节点，把它的工作区（代码、分数、报错）交给 coding agent，让它分析原因并改出更好的版本，评测后成为该节点的子节点。树上每条"父 → 子"的边都是一次精炼，花一次 agent 调用。选叶子 = 在现有思路上深挖（exploit）；选根 r = 从初始程序重新起步、开新分支（explore）。论文中每轮 "10 条分支 × 11 次" 即 BRANCHES=10、REFINE=10：每条分支 1 次从根出发 + 最多 10 次精炼。
N回放中揭示出的非根节点数 = 策略用掉的尝试次数 = 成本（根是初始程序，不算尝试）。
k*回放结束时完成的回合数（每回合并行跑一批，全部跑完才进入下一回合）≈ 墙钟时间。小写 k 是回合编号；大写 K₁、K₂ 是在线 / 回放的回合上限。
N / k*平均每回合跑几个 = 并行度。同样 6 次尝试，3 回合跑完（并行度 2）比 6 回合跑完（并行度 1）快一倍。所以目标函数里 −β₁·N 逼策略省钱，+β₂·N/k* 逼策略把 worker 塞满；分母写成 max{1, k*} 只是防止除以零。

设定

任务：让 agent 写一个程序，分数越高越好。最多 W = 2 个 agent 并行。起点策略 π₁ 是人写的"parallel refining"：开 2 条分支，每条精炼到深度 3。策略本身就是一段 Python 代码：

# π₁ 原策略：开 2 条分支，每条精炼到深度 3
def select(tree):
    batch = []
    if num_branches(tree) < 2:
        batch.append(ROOT)                          # 开新分支
    batch += [l for l in leaves(tree) if depth(l) < 3]   # 继续精炼
    return batch[:W]                                # 返回空列表 = 停止

第 1 步：在线跑一轮（真花钱）

π₁ 指挥 agent 真实运行，花了 6 次调用，得到发现树 T₁，存入历史 $\mathcal{H}_1=\{\mathcal{T}_1\}$：

图 2（本报告绘制）：第 1 轮在线运行得到的发现树 T₁。每条边是一次精炼 / 一次 agent 调用。

第 2 步：内层循环——LLM 连续改写策略代码，每版都在 T₁ 上回放

回放规则：选非根节点 → 揭示它在记录中的子节点和分数；选根 r → 揭示一条尚未揭示分支的第一个节点；记录里没有的 → 什么也得不到；策略只看得到已揭示的分数。每个版本的评估都只是查表，不调用 coding agent。论文中每次学习评估 M = 4 个版本（当前策略 + 连续改写 3 次）；每次改写都能看到之前所有版本的回放结果，所以是一条链，不是一次并列提多个。

版本 0 = 原策略 π₁ 的回放：

回合可选节点选择揭示
1r{r}A1 = 0.40
2r, A1{r, A1}B1 = 0.30，A2 = 0.42
3A2, B1{A2, B1}A3 = 0.43，B2 = 0.55
4A3, B2{B2}（A3 已到深度 3）B3 = 0.80
5A3, B3都到深度 3 → 返回空批次，结束–

结果：最高 0.80，N = 6，k* = 4。

版本 1：LLM 读了回放轨迹，发现 A 分支 0.40 → 0.42 → 0.43 几乎不涨还多花了调用，于是加入剪枝：

# 版本 1：某一步涨幅不足 0.05 的分支不再精炼
alive = [l for l in leaves(tree) if depth(l) < 3 and gain(l) >= 0.05]
回合可选节点选择揭示
1r{r}A1 = 0.40
2r, A1{r, A1}B1 = 0.30，A2 = 0.42
3A2, B1A 只涨 0.02 → 剪掉；选 {B1}B2 = 0.55
4B2{B2}B3 = 0.80
5B3深度 3 → 返回空批次，结束–

结果：最高 0.80，N = 5，k* = 4。A3 从未被揭示，相当于省下一次调用。注意第 3 回合剪掉 A 时，策略并不知道 B 以后能到 0.80，它只看得到 B1 = 0.30——这就是 prefix-only、"不准偷看"的约束。

版本 2：LLM 看到"剪枝有效"，就剪得更狠——只保留当前分数最高的那条分支。回放：前两回合同上；第 3 回合 A2 = 0.42 > B1 = 0.30，于是剪掉还没起势的 B，只选 {A2} 得到 A3 = 0.43；第 4 回合 A 也到深度 3，结束。最高 0.43，N = 4（A1、A2、A3、B1），k* = 3。

版本 3：LLM 看到"版本 2 剪过头了"，改回版本 1 的涨幅阈值，并加一条"剪掉一条分支后，用空出的 worker 开新分支"。但 T₁ 中根下只记录了 A、B 两条分支，开新分支揭示不出任何东西，所以在 T₁ 上的回放结果与版本 1 相同。这也体现了回放的局限：它无法给记录之外的行为加分。

第 3 步：按目标函数打分并选择

$V = \max s - \beta_1 N + \beta_2 \cdot N/k^\star$，取 $\beta_1 = 0.02,\ \beta_2 = 0.01$：

版本最高分Nk*−β₁N+β₂N/k*V
0（原策略）0.8064−0.12+0.0150.695
1（涨幅剪枝）0.8054−0.10+0.01250.7125
2（只留最好分支）0.4343−0.08+0.01330.363
3（剪枝 + 补开新分支）0.8054−0.10+0.01250.7125

从所有版本里选回放分最高的（不是直接用最后一版），所以改坏的版本 2 不会被部署；又因为版本 0 也在候选中，最差也就是保持原样。版本 1 与 3 并列，假设选中版本 1 作为 π₂。

第 4 步：外层循环——部署、产生新世界、再做梦

  1. 第 2 轮在线：π₂ 真实运行，产生全新的树 T₂。agent 有随机性，T₂ 与 T₁ 不同；剪枝省下的调用让好分支挖得更深。$\mathcal{H}_2=\{\mathcal{T}_1,\mathcal{T}_2\}$。
  2. 第 2 次做梦：以 π₂ 为版本 0 再连续改写 3 次，每个版本要在 T₁ 和 T₂ 上都回放并取平均分。只在 T₁ 上好、在 T₂ 上差的版本会被平均分淘汰——这就是 "Evolving Worlds"：用来做梦的世界越积越多，评估越可靠、越不容易过拟合单棵树。
  3. 部署 π₃ → 产生 T₃ → 在 T₁、T₂、T₃ 上做梦……循环到设定轮数（如 Lasso 为 5 轮）。
外层循环（t）内层循环（m）

一句话

内层 = 让 LLM 当程序员，用回测分数做反馈，不断改一个调度算法；外层 = 定期用真实运行扩充回测用的历史。把这个例子放大到每轮 110 次调用、5–10 轮、复杂得多的策略代码，就是论文的实验；图 6 中 ConvDiv 每轮尝试数从 110 降到 50、平台期又回升到 92，正是这种学到的"该省就省、卡住就加码"的行为。

5. 实验

对照基线 Recursive Fixed Exploration：与 Dream-RSI 完全相同的 agent、评测器、初始化和预算，起点都是人工设计的 "parallel refining" 策略（多个独立工作区并行，各自精炼自己的候选）。第 1 轮两者完全一致；之后基线策略固定，Dream-RSI 通过回放修订策略。这是一个干净的控制变量设计。

成本口径：累计 discovery-agent 调用次数。每轮预算上限：Gemini-3.1 Pro 为 10 工作区 × 最多 11 步 = 110 次；Gemini-3.7-Flash 为 32 × 20 = 640 次。

发现出的求解器长什么样

SimpleTES 的解法按维度在 LARS 与坐标下降之间切换；Dream-RSI 找到的是在活跃集优化内部自适应的 C++ 实现（Eigen + OpenMP）：

  • Strong rule 筛选；
  • 基于 Cauchy–Schwarz 的 KKT 剪枝：用上界证明特征可以保持非活跃，只有上界无法证明时才重算精确梯度（仅在 $p\ge500, n\ge150$ 时启用）；剪枝失效时整体刷新梯度；
  • 不相交分区的活跃集簿记（O(1) swap-delete）、惰性 Gram 矩阵构造、64 字节对齐缓冲区、无分支软阈值函数等硬件感知实现。

6. 分析与消融

6.1 历史当"模拟器" vs 当"提示"

在 ConvDiv 上，把历史以提示词级语义指导（告诉 agent 未来该往哪个方向搜）的方式喂进去，在同预算下，无论 Fixed 还是 Dream-RSI 都不如不加指导。作者解释：强语义方向偏置会在多线程并行搜索时过度约束搜索、降低多样性。这正是论文核心主张的反证——历史更适合用来评估策略，而不是直接告诉 agent 做什么。（正文仅给图，无具体数值。）

6.3 进化出的策略的行为特征

论文没有单独的 case study 节，以下来自附录 B.2 的 replay-policy prompt 与图 6：

  • 组合式批次：每轮构造一个最多 max_parallelism 个独立候选的"投资组合"，混合 exploit、explore（新根或欠探索分支）和至多一个 recovery 动作；同一批次不能同时包含父与子。
  • 谨慎剪枝：只有累积证据显示"不可恢复"或"反复无望"才关闭分支，单次浅层低分不足以剪枝。
  • 可修复错误不判死刑：形状、mask、内存布局等实现错误保留资格，不当作算法失败。
  • β 作为每回合标量：控制宽度、耐心、剪枝强度，在轮间选定，不在 solve() 内调。
  • plan_grid：每个在线轮前，仅用前缀安全的历史决定分支数与精炼步数。

8. 批判性评价

优点

  • 想法简洁而通用：只加一层编排，不改 agent、评测器；任何树状提案–评测系统都能套用。
  • 控制变量干净：Recursive Fixed Exploration 与 Dream-RSI 只差"是否离线改策略"，第 1 轮完全重合。
  • 成本收益显著：一致地以更少调用达到相当或更好效果，跨三类任务成立。
  • 防作弊意识：prefix-only、不读未揭示分数等约束，对回放评估的可信度很关键。

局限 / 疑问

  • 回放保真度未量化：模拟器只能揭示记录过的子节点，策略在记录之外的行为（同一节点多次采样、更深的链）完全无法评估；回放分与在线表现的相关性没有报告。这是 off-policy 评估的经典覆盖偏差问题。
  • 单调性很弱：$\bar V^{m^\star}\ge\bar V^0$ 只在固定历史上成立，且多次 argmax 选择存在对历史过拟合（winner's curse）风险。
  • 与外部基线的比较不对等：SimpleTES、AlphaEvolve 等数字多取自原文，backbone 不同（gpt-oss-120b vs Gemini），"162× 更省"应理解为系统级对比而非纯方法对比。
  • 无方差 / 多种子结果：发现过程高度随机，单次运行的差异（如 Sum–Diff 1.145427 vs 1.144047）是否显著不得而知。
  • 关键超参正文未披露：正文没写 $\beta_1,\beta_2,K_1,K_2,M$，需要去代码里查（M=4、β 网格、λ=0.05 等见第 10 节）；式 1 与实际优化的 Pareto-AUC 目标也不完全一致。
  • 离线阶段成本未计入：成本只统计 discovery-agent 调用，策略开发 agent 的 M 次改写及回放的 token / 时间开销没有被纳入"省 162×"的口径。
  • 没有专门的局限性章节；任务集与轮数有限。

9. 学习要点 & 延伸问题

三句话带走
  1. 代码进化发现系统的瓶颈正从"生成能力"转向"探索策略"——选谁、开多少、何时停。
  2. 跑完的发现树是一个零成本、零模型误差的回放模拟器，可在上面 off-policy 评估任意新策略。
  3. "在线采集 → 离线改写策略 → 选最优部署"的递归循环，让探索策略随世界（历史）一起进化，主要收益是大幅省算力。

值得自己思考 / 动手的问题

  1. 能否给回放模拟器加一个学出来的转移模型（预测未记录节点的分数分布），把 Dream-RSI 从"非参数回放"推广到"Dyna 式"混合模拟？代价与收益如何？
  2. 如何度量回放保真度？例如：在同一棵树上，用留出的一部分分支检验回放排序与在线排序的 Kendall τ。
  3. 多次 argmax 选择的过拟合：能否借用 off-policy RL 的保守估计（如下置信界、bootstrapped 历史）来选策略？
  4. 把成本项 $\beta_1$ 换成真实的墙钟 / 美元成本，并计入策略开发 agent 的开销，结论还成立吗？
  5. 迁移性：在 Lasso 任务上进化出的探索策略，直接用在 KernelBench 上是否仍优于人工策略？（论文未做跨任务迁移实验。）
