01一句话理解 AWQ

先测量哪些输入通道的激活通常较大，再放大这些通道对应的权重列、同时把输入缩小相同倍数；搜索让模块输出误差最小的缩放强度，最后统一做低比特分组量化。

AWQ 是 Activation-aware Weight Quantization 的缩写，中文通常译为“激活感知权重量化”，来自 MIT Han Lab，获 MLSys 2024 最佳论文。它是一种面向 LLM 的低比特、训练后、仅权重量化方法，常见配置是 INT4 权重与 FP16/BF16 激活，即 W4A16。[1]

看什么？

看激活分布，而不是只看权重绝对值。权重造成的影响还取决于它乘上的输入激活。

保护谁？

保护高激活输入通道对应的权重列；最终对所有通道采用连续缩放，而非只保存一个二值的“重要权重名单”。

怎么保护？

通过数学上等价的逐通道缩放重新分配量化分辨率，不引入不规则的 INT4 / FP16 混合权重存储。

不做什么？

不反向传播、不重新训练，也不做 GPTQ 式的逐列量化与剩余权重误差补偿。

02从朴素权重量化出发

对一个线性层 y = Wx，Round-to-Nearest（RTN）把每个权重映射到最近的量化网格点。以 b bit 非对称量化为例：

q = clip(round(w / Δ) + z, 0, 2b − 1)
ŵ = Δ · (q − z)

其中 Δ 是量化步长，z 是零点。4 bit 只有 16 个整数级别。实际 AWQ 通常采用 group-wise 量化：每个输出通道内再按固定数量的输入通道分组，各组拥有自己的 scale 和 zero point。论文与官方示例都用 group_size = 128。[1][3]

“Weight-only”到底量化的是什么？

  • 存储与搬运：权重以 INT4 等低比特形式保存，配套保存高精度量化参数。
  • 计算：推理内核把权重即时反量化到 FP16/BF16，再与高精度激活计算；不是整个矩阵乘法都在 INT4 上完成（原因见第 11 节：硬件没有 INT4 × FP16 的乘法指令）。
  • 主要收益：降低权重显存占用与显存带宽压力。对自回归 decode 这类受权重读取带宽限制的场景尤其有价值。
4 bit 不等于总显存恰好缩小 4 倍
仅看理想权重 payload，7B 参数从 FP16 到 INT4 约由 14 GB 降到 3.5 GB（按十进制 GB）。实际还要加上 scale / zero point、未量化层、KV cache、激活与运行时缓冲区，因此总显存不会严格缩小 4 倍。

03两个关键观察

观察一：权重并不同等重要

论文的消融实验发现，在 INT3、group size 128 的设置下，仅把约 0.1%–1% 的显著权重通道保留为 FP16，就能相对朴素 RTN 明显改善量化质量。[1]

观察二：应根据激活，而不是权重大小选重要通道

同一个实验里，按什么标准挑这 1% 通道，结果天差地别（OPT-6.7B，INT3-g128，WikiText-2 困惑度，越低越好）：

数据来自论文 Table 1。按权重大小挑和随机挑几乎没用；按激活挑，0.1% 就把困惑度从 23.54 拉回 11.58。

原因很直接：设第 j 个输入通道上的权重量化误差为 δwij，则输出误差为

δyi = Σj δwij · xj

同样大小的权重误差，乘上更大的激活就造成更大的输出误差。因此，输入通道的典型激活幅度是权重误差敏感度的有用代理。

“保留 1% FP16”是动机实验，不是 AWQ 最终的存储方式
混合精度格式对硬件不友好（不规则访存、需要专门内核）。AWQ 最终改用逐通道缩放来“保护”这些通道，目标模型仍可统一打包为低比特权重。

04核心操作：等价逐通道缩放

4.1 不改变原始线性变换

令每个输入通道 j 有一个正缩放系数 sj，组成对角矩阵 S。把权重第 j 列乘以 sj，同时把输入第 j 维除以 sj：

未量化时，数学输出完全相同 y = Wx = (WS)(S−1x)

AWQ 真正量化的是变换后的权重 WS，因此实际计算近似为：

ŷ = Q(WS) · S−1x

注意 s 是按输入通道定义的，同一列的所有输出行共用一个 sj；它和每个量化 group 内部的步长 Δ 是两回事。

4.2 为什么放大显著权重能降低有效误差？

只看一个显著权重。原量化步长为 Δ；把它乘以 s > 1 后量化，再除以 s 回到原坐标系，新步长记为 Δ′。舍入误差的期望大致不变（约 0.25 个步长），所以：

新误差 / 原误差 ≈ (Δ′ / Δ) · (1 / s)

只放大一个元素，通常不会改变整组的最大值，即 Δ′ ≈ Δ，于是这个权重的有效误差约缩小到 1/s。但 s 太大时，它会变成组内最大值、撑大 Δ′，组内其他普通权重的误差随之放大。论文实测（OPT-6.7B，INT3-g128，只放大 1% 显著通道）：[1]

s1（RTN）1.251.524

所以 AWQ 不是“缩放越大越好”，而是在显著通道和其他通道之间重新分配有限的量化分辨率。这就是需要搜索缩放强度的原因。论文中完整 AWQ 在该设置下 PPL 为 11.39，与“1% 保留 FP16”的 11.39 持平，但不需要混合精度存储。

4.3 反向缩放到哪里去了？

S−1 被吸收进前一个算子，推理时零额外开销。官方实现有三种吸收方式：[4]

  • Norm → Linear：LayerNorm / RMSNorm 的 weight（及 bias）除以 s，后续 Linear 的对应输入列乘以 s（scale_ln_fcs）。
  • Linear → Linear：前一个 Linear 的对应输出行除以 s，后一个 Linear 的输入列乘以 s（scale_fc_fc）。例如 v_proj → o_proj（注意力输出对 V 是逐通道线性的）、up_proj → down_proj（SwiGLU 输出对 up 是逐元素线性的）。
  • 激活函数 → Linear：GELU 等非线性不能直接穿过，官方用 ScaledActivation 包一层显式的逐通道除法。

5.1 缩放搜索（auto_scale.py）

缩放系数被参数化为 s = sXα，其中 sX 是逐通道平均激活幅度，只需搜索一个标量 α。以下伪代码按官方代码整理：[4]

# x: 缓存的该组 Linear 的输入 [n_tokens, c_in] x_mean = x.abs().mean(dim=0) # get_act_scale：每个输入通道一个数 for i in range(20): # n_grid = 20 alpha = i / 20 # 0, 0.05, ..., 0.95（不含 1.0） s = x_mean.pow(alpha).clamp(min=1e-4) s = s / sqrt(s.max() * s.min()) # 归一化，让缩放围绕 1 分布 for fc in linears2scale: # 共享同一输入的多个 Linear 用同一个 s fc.weight = Q(fc.weight * s) / s # 伪量化后再除回去 loss = mean((block(x) - block_fp16(x)) ** 2) # 看整个被检查模块的输出 记录最小 loss 对应的 s；恢复原权重 # 最后把 1/s 融进前一个算子，把 s 乘进这些 Linear 的列

对 Llama / Qwen2 结构，每个 Transformer block 搜索 4 组缩放：

前一个算子（吸收 1/s）被放大的 Linear搜索时比较谁的输出
input_layernormq_proj, k_proj, v_proj整个 self_attn
v_projo_projo_proj（仅当二者权重形状相同时才做，GQA 模型会跳过）
post_attention_layernormgate_proj, up_proj整个 mlp
up_projdown_projdown_proj

细节：代码里定义了同时使用权重统计的 get_weight_scale，但默认搜索只用激活统计。后来 NVIDIA ModelOpt 的 awq_lite 和 llm-compressor 的 duo_scaling 都加入了“激活α / 权重1−α”的变体（见第 12 节）。

5.2 权重裁剪搜索（auto_clip.py）

  • 在缩放之后进行，使用已经除以 s 的输入特征。
  • 对每个“输出通道 × group”，把截断阈值设为原最大值的 100%、95%、…、55%（10 档），对称截断后伪量化。
  • 从校准 token 中均匀抽 512 个，计算该 group 局部输出的 MSE，取最小者。
  • 名字含 q_、k_、query、key、Wqkv 的层跳过裁剪（代码注释：QK 相乘后难以精确裁剪）。[7]

5.3 整体流程（pre_quant.py）

  1. 准备校准集

    默认取 pile-val 数据，n_samples=512、seqlen=512；不需要标签、损失反传或参数训练。[6]

  2. 逐 block 处理

    对第 i 个 block：挂 hook 缓存所有 Linear 的输入，同时算出该 block 的 FP16 输出作为下一个 block 的输入。

  3. 缩放搜索并应用

    按 5.1 搜索 4 组缩放，应用到权重，并把缓存的输入同步除以 s。

  4. 裁剪搜索并应用

    按 5.2 搜索并截断权重。

  5. 最后统一量化

    真正的 INT 量化与打包在这些变换都完成之后进行（--q_backend real）。

一个和 GPTQ 不同的细节
官方 AWQ 在应用缩放和裁剪之前就已算出下一个 block 的输入，所以后续 block 看到的是 FP16 模型的激活，前面 block 的量化误差不会传递下去。GPTQ 则用“已量化 block 的真实输出”作为下一层输入，让后面的层能看到并补偿前面的误差。

06一个可复现的小实验

先看最直观的版本：两个输入通道平均激活为 a = [8, 1]，取 α = 0.5，则 s ∝ [√8, 1] ≈ [2.83, 1]。第一列权重获得约 2.83 倍的相对放大，推理时第一维输入做对应缩小。

下面用一个更接近真实的玩具层，看看 α 的选择如何影响误差。设定：

  • 一个 Linear：256 个输出 × 512 个输入通道，权重服从拉普拉斯分布。
  • 输入通道相互独立；其中 5 个通道（约 1%）激活标准差为 20，其余为 1。
  • INT3 对称量化，group size 128，用期望输出误差 E‖(W − Ŵ)x‖² 衡量（通道独立时可精确计算）。

RTN 下，这 1% 的显著通道贡献了全部输出误差的 79.9%。这就是“保护少数通道收益巨大”的原因。

为什么是 U 形曲线

α 增大时，显著通道的误差占比一路下降（α=0.4 时 26%，α=0.95 时 5%），但它们撑大了所在 group 的步长，其他通道误差上升。两者平衡在 α≈0.4。

这个玩具例子里 AWQ 没有追上“保留 1% FP16”（35.9% vs 20.1%），而论文在真实模型上两者持平（第 4 节）。差距取决于权重和激活的真实分布，玩具结果只用于说明机制，不代表真实模型的数值。

展开实验脚本（纯 Python，无依赖）
import math, random random.seed(42) R, C, G, BITS = 256, 512, 128, 3 # 256 个输出、512 个输入通道、group=128、INT3 salient = [37, 201, 388, 450, 99] # 约 1% 的输入通道激活很大 sigma = [20.0 if j in salient else 1.0 for j in range(C)] a = [s * math.sqrt(2 / math.pi) for s in sigma] # a_j = E|x_j|（高斯分布） def laplace(b=0.02): u = random.random() - 0.5 return -math.copysign(1, u) * math.log(1 - 2 * abs(u)) * b W = [[laplace() for _ in range(C)] for _ in range(R)] QMAX = 2 ** (BITS - 1) - 1 def quant_row(row, keep=()): out = row[:] for g in range(0, C, G): idx = [j for j in range(g, g + G) if j not in keep] d = max(abs(row[j]) for j in idx) / QMAX for j in idx: out[j] = d * max(-QMAX, min(QMAX, round(row[j] / d))) return out def out_mse(Wq): # E||(W - Wq) x||^2，输入通道独立 => Σ δw² σ² return sum((W[r][j] - Wq[r][j]) ** 2 * sigma[j] ** 2 for r in range(R) for j in range(C)) / R def scaled_quant(s): return [[v / s[j] for j, v in enumerate(quant_row([W[r][j] * s[j] for j in range(C)]))] for r in range(R)] base = out_mse([quant_row(r) for r in W]) print(f"keep 1% FP16: {out_mse([quant_row(r, set(salient)) for r in W]) / base:.1%}") for k in (2, 4): print(f"salient x{k}: {out_mse(scaled_quant([k if j in salient else 1 for j in range(C)])) / base:.1%}") for i in range(20): # 与官方实现相同的 α 网格 alpha = i / 20 s = [t ** alpha for t in a] n = math.sqrt(max(s) * min(s)) s = [t / n for t in s] print(f"alpha={alpha:.2f}: {out_mse(scaled_quant(s)) / base:.1%}")

07从 OBS / GPTQ 视角看 AWQ

AWQ 和 GPTQ 优化的是同一个逐层目标：

min ‖WX − ŴX‖²，其 Hessian 为 H = 2XXT

把一行权重的误差记为 δw，输出误差就是 δwT(XXT)δw。如果各输入通道近似不相关，它约等于

Σj δwj2 · Σt xjt2 = Σj δwj2 · Hjj / 2

可以这样理解（这是我的解读，不是论文原话）：AWQ 的激活统计 mean|xj| 相当于用一阶矩代替二阶矩，廉价地近似了 diag(H)。放大第 j 列，就是把更多量化分辨率分给 Hjj 大的通道。

AWQGPTQ
用到的二阶信息只用“对角”式的逐通道激活统计完整 H（含通道间相关性），通过 Cholesky 分解使用
改变的是什么量化网格如何分配（通过缩放 + 裁剪），取整仍是 RTN取整决策：逐列量化，并更新剩余权重来补偿
自由度每组只搜一个标量 α（20 档）每个权重的取整都依赖之前的误差
过拟合校准集的风险低：只统计平均幅度较高：直接拟合校准数据的协方差
是否传递前层误差否（下一层输入来自 FP16 模型）是（下一层输入来自已量化模型）
两者是正交的：AWQ 先把网格“摆对”，GPTQ 再把取整“做对”，可以叠加使用。论文 Table 9 中 INT2-g64：OPT-6.7B 的 GPTQ PPL 16.65，AWQ+GPTQ 降到 15.71；OPT-13B 从 16.74 降到 13.25。[1]

与 RTN、GPTQ、SmoothQuant 的总体区别

方法主要量化对象核心思路校准 / 训练与 AWQ 的关键差别
RTN通常为权重直接舍入到最近网格点不需要校准最简单，没有利用激活敏感度。
AWQ权重，典型 W4A16激活统计 + 逐通道等价缩放 + 分组量化少量校准前向；无反传重点是保护显著输入通道。
GPTQ[8]经典方法为仅权重用输入 Hessian 逐列量化，并更新未量化权重来补偿误差需要校准数据；顺序更新二阶误差最小化与权重间补偿。
SmoothQuant[9]权重和激活，典型 W8A8同样是等价逐通道缩放，但目的是把激活的量化难度迁移给权重需要校准统计目标是让激活也能低比特；AWQ 保持激活高精度。

08AWQ vs GPTQ：效果、应用与量化开销

一句话：4-bit、group 128 时两者基本打平，谁赢取决于实现细节和评测方式；GPTQ 在更低比特、不分组时更稳，AWQ 对校准数据更鲁棒；量化开销在同一量级，但资源消耗的结构不同。

GPTQ 占优的情况

3-bit 及以下、不分组（per-channel）量化；开放式生成和代码任务（调优后）；作为旋转类方法（QuaRot / SpinQuant）后面的取整步骤。

AWQ 占优的情况

校准数据少或与实际负载分布不一致；多模态和指令模型（论文中 VLM 结果明显优于 GPTQ）；希望流程简单、不易过拟合。

注意：许多博客给出的“AWQ 比 GPTQ 高 x 分”的表格没有说明评测框架、group size、act-order 和校准集，结论经常互相矛盾，不宜引用。上表只收录了公开了设置的论文。

09GPTQ / AWQ 量化之后还有 outlier 吗？

有。“量化”改变数值表示，不等于“消除 outlier”。必须区分激活 outlier 与权重 outlier。

激活 outlier

  • 经典 GPTQ 与 AWQ 都是 weight-only，激活仍以 FP16/BF16 计算，因此激活 outlier 基本仍然存在。
  • GPTQ 使用校准激活估计 Hessian；它利用这些统计来降低输出误差，但并不对激活做平滑。
  • AWQ 的缩放会把激活除以 s，大激活通道确实被缩小了，但目的是保护权重；由于激活本来就不量化，这只是副作用。

权重 outlier

  • 反量化后的某些权重仍可能相对同组其他权重特别大。
  • 大极值会拉大量化步长，让普通权重能利用的有效级别减少。group-wise 量化、AWQ 的缩放与裁剪都在缓解这一问题，而不是保证 outlier 消失。
  • GPTQ 不会把权重 outlier 单独保留为 FP16；它依靠分组量化与误差补偿控制整体输出损伤。SpQR 等扩展方法才会把 outlier 单独保留为高精度。

10为什么 W4A16 能加速：roofline 与 TinyChat

论文在 RTX 4090 上用 FasterTransformer 跑 FP16 的 Llama-7B（batch 1）：处理 200 token 的 prompt 只要 10 ms，生成 20 个 token 却要 310 ms。瓶颈在生成阶段。[1]

  • 4090 峰值算力 165 TFLOPS、带宽 1 TB/s，算术强度低于 165 FLOPs/Byte 的负载都受带宽限制。
  • FP16 生成阶段的算术强度约为 1，访存量又以权重为主，远远受带宽限制。
  • 权重换成 4 bit，读同样的权重只要 1/4 的字节，算术强度约提高到 4，理论上限提升约 4 倍。

TinyChat 把理论收益变成实际加速

  • 即时反量化并与矩阵乘融合：论文原话是“硬件不提供 INT4 与 FP16 之间的乘法指令”，所以必须先把整数反量化成 FP16 再算；融合进 GEMM/GEMV 内核，避免把反量化结果写回显存。
  • 按 SIMD 宽度重排权重：ARM NEON 128 位寄存器中按 w0, w16, w1, w17, … 排列，3 条 SIMD 指令就能解包 32 个权重（常规排列每个权重要 3 条标量指令），最多快 1.2 倍。GPU 上按 w{0,2,4,6,1,3,5,7} 打包。
  • 算子融合：LayerNorm 全部融合；QKV 投影融合；位置编码在线计算；KV cache 在 attention 内核里更新。4090 上单个 FP16 内核只需约 0.01 ms，和内核启动开销相当，减少内核数量直接带来加速。

结果：相对 Hugging Face FP16 实现平均快 3.2–3.3 倍，4090 上最高 3.9 倍，Jetson Orin 上 3.5 倍；能在 64 GB 的 Jetson Orin 上跑 Llama-2-70B，在 8 GB 显存的笔记本 RTX 4070 上以 30 token/s 运行 13B 模型。

加速只在受带宽限制时成立
batch 变大或处于 prefill 阶段时，负载转为受算力限制，W4A16 的加速会消失，反量化开销甚至让它更慢。详见下一节的 Marlin 数据。

11硬件层面：FP4 / INT4 × FP16 有原生加速吗？

主流 GPU 都没有“4 bit × 16 bit”的矩阵乘指令。W4A16 的加速来自软件内核（读 4 bit 权重 → 寄存器里反量化 → 用 FP16/BF16 Tensor Core 计算），只在受带宽限制时有效。硬件原生加速的是 FP4 × FP4，以及 FP4 × FP8（按 FP8 速率）。

11.3 大 batch 也想加速怎么办

  • W4A8：4 bit 权重 × FP8 激活。在 Blackwell 上可以直接用 kind::f8f6f4；在 Hopper 上把 INT4 反量化成 FP8 再算。既省显存，又能用 FP8 算力。
  • W4A4（NVFP4 / MXFP4）：权重和激活都是 FP4，在 Blackwell / MI355X 上用最高的 FP4 算力；代价是激活也要量化，需要 SmoothQuant、旋转等技巧。
  • 实例：gpt-oss 的 MXFP4 MoE 权重在 Hopper 上走 BF16 × MXFP4（权重即时反量化，如 Triton matmul_ogs、Marlin、FlashInfer CUTLASS）；在 Blackwell 上可以走 MXFP8 × MXFP4（FlashInfer 的 TRT-LLM / CUTLASS 内核），也可以走 BF16 × MXFP4。[20]
  • llm-compressor 文档也写明：NVFP4 / MXFP4 checkpoint 在 Ampere 及以上都能加载，但老 GPU 上走的是 weight-only Marlin 内核，激活保持 16 位，只省显存，不加速激活计算。[21]

122026 年的工具链现状

  • 官方 llm-awq（MIT Han Lab）：研究参考实现和 TinyChat，仍在维护（已支持 Qwen2、InternVL3、VILA 等）。[3]
  • AutoAWQ：2025 年宣布弃用，仓库归档；最后测试的组合是 Torch 2.6 + Transformers 4.51.3。README 指向 vLLM 的 llm-compressor 和 MLX-LM。[22]
  • llm-compressor AWQModifier：移植自 AutoAWQ，复现 Llama-2-7B g128 的 PPL 为 5.612（论文 5.60）。它只负责缩放，必须配合 QuantizationModifier 才产出量化模型；用 AWQMapping（smooth_layer → balance_layers）描述缩放位置，与官方的 4 组缩放一致；提供 duo_scaling 选项；最初的移植版去掉了裁剪逻辑。[23]
  • NVIDIA ModelOpt：INT4_AWQ_CFG（W4A16）、W4A8_AWQ_BETA_CFG（INT4 存储、FP8 计算）、NVFP4_AWQ_LITE / CLIP / FULL。其 awq_lite 默认 α 步长 0.1，且默认 use_weight_scale=True，即 s ∝ actα / w1−α，与论文只用激活统计不同。[19]
  • TensorRT-LLM：支持 W4A16 AWQ、W4A8 AWQ（以及对应的 GPTQ 版本）。
  • GPT-QModel：已成为 HF Transformers / Optimum / PEFT 的量化后端，同时取代了 AutoGPTQ 和 AutoAWQ。
趋势：AWQ 的核心思想（基于激活的等价缩放）已经变成一种通用的“量化前变换”，可以和 INT4、FP8、NVFP4 等格式组合使用，不再只绑定 W4A16。

用 llm-compressor（面向 vLLM 部署）

新版 API 中 AWQ 只负责缩放，量化交给 QuantizationModifier；配方再交给 llm-compressor 的 oneshot 流程执行。[23]

from llmcompressor.modifiers.transform.awq import AWQModifier from llmcompressor.modifiers.quantization import QuantizationModifier recipe = [ AWQModifier(duo_scaling="both"), QuantizationModifier(ignore=["lm_head"], scheme="W4A16_ASYM", targets=["Linear"]), ]

上线前检查清单

  • 先确定格式再选算法：Ampere 选 W4A16；Hopper 优先 FP8 或 W4A8；Blackwell 考虑 NVFP4 / MXFP4。AWQ 和 GPTQ 是实现这些格式的校准算法。
  • 确认后端兼容性：模型架构、AWQ 格式版本、对称性、zero point、group size 和目标硬件是否受支持。
  • 让校准数据有代表性：通用模型可使用多样文本；代码、数学、多语言或垂直领域模型应覆盖目标分布。
  • 同时评精度与真实任务：困惑度只是一个指标，还应覆盖指令遵循、推理、代码、长上下文及业务回归集。Kurtic et al. 的结果说明学术基准打平时，开放式任务仍可能有差距。
  • 按真实 batch 分布测速度：W4A16 对低并发 decode 有效，高并发时加速会消失。分别测 prefill 和 decode。
  • 测端到端显存：包含权重元数据、KV cache、激活和运行时，而非只比较理论权重 bit 数。
  • 使用优化内核：只有低比特存储而缺少高效的反量化与矩阵乘内核时，可能省显存但不提速，甚至更慢。

14局限与常见误区

误区 1：AWQ 把 1% 权重永久保留为 FP16。
不是。1% 是论文中的动机实验；最终方法用等价的逐通道缩放保护显著通道，避免不规则的混合精度。
误区 2：AWQ 按权重绝对值识别重要权重。
不是。关键恰恰是参考激活分布；论文实验中按权重大小挑选几乎和随机一样无效。
误区 3：缩放系数直接等于激活均值。
不完整。官方实现以 aα 构造候选，在 α ∈ {0, 0.05, …, 0.95} 上搜索，并做归一化和截断，以模块输出 MSE 选优。
误区 4：AWQ 对每个 Linear 单独搜索。
不是。共享同一输入的多个 Linear（如 q/k/v、gate/up）共用一个 s，并以整个 attention 或 MLP 模块的输出误差为目标。
误区 5：W4A16 表示权重和激活都是 4 bit。
不是。W4A16 表示 4 bit 权重、16 bit 激活，矩阵乘使用反量化后的高精度值计算。
误区 6：W4A16 在任何 batch 下都更快。
不是。batch 增大后负载转为受算力限制，加速从约 3 倍降到 1.2 倍左右（第 11 节）。
误区 7：Blackwell 有 FP4 Tensor Core，所以 FP4 权重 × BF16 激活也能直接算。
不能。FP4 Tensor Core 要求另一方也是 FP4（或在 f8f6f4 模式下是 FP6 / FP8）；激活保持 BF16 时仍需软件反量化。
误区 8：AWQ 会消除激活 outlier。
不会。它的目的是降低权重量化误差；要把激活也量化成低比特，需要 SmoothQuant、旋转等面向激活的技术。

实际局限

  • 依赖分组量化：不分组时 AWQ 明显不如 GPTQ（Llama-2-7B W3A16：24.00 vs 8.37）；2-bit 时会崩溃，需要和 GPTQ 等方法叠加。
  • 依赖校准分布：比 GPTQ 鲁棒，但“不需要训练”不等于“不可能过拟合校准集”。
  • 有量化开销：需要缓存激活、逐 block 网格搜索，大模型和 MoE 的激活缓存可能很占内存。
  • 格式不等于性能：加速高度依赖内核、硬件、batch、序列长度及 prefill/decode 阶段。
