一、TL;DR（一句话总结）

Qrita 是一个基于 枢轴搜索（pivot-based search）的 GPU Top-k / Top-p 算法，通过高斯 σ 截断大幅缩小搜索空间、四元枢轴搜索减半迭代次数、重复值处理保证确定性，在保持与排序算法完全一致的严格语义前提下，吞吐比 vLLM / SGLang / FlashInfer 等 SOTA 方案最高提升 2×，端到端服务吞吐提升 1.41×，且内存占用仅为一半。

论文亮点：Qrita 已经被合入 vLLM 主分支，成为其默认的 GPU Top-k / Top-p 采样器。

二、研究背景与问题动机

2.1 为什么关心 Top-k 和 Top-p？

在 LLM 采样式生成中，Top-k 和 Top-p（nucleus）是控制生成质量与多样性的两大截断算子：

  • Top-k（Fan et al. 2018）：保留 logit 最高的 k 个 token，剪掉长尾低概率 token，避免不连贯输出。
  • Top-p（Holtzman et al. 2020）：动态选取累计概率 ≥ p 的最小 token 集，兼顾多样性。

2.2 面临的 GPU 实现挑战

现代 LLM 的词表规模已达 100K ~ 260K（如 Gemma3 词表 262208），Top-k / Top-p 实现存在以下痛点：

排序法（vLLM 等）

对全词表排序。语义精确但计算和内存开销巨大：分块比较导致跨步内存访问、需要大量中间缓冲区，在 GPU 上不友好。

拒绝采样法（FlashInfer / SGLang）

用 Dual Pivot Rejection Sampling 只返回单个 token，属于随机等价而非严格 Top-k / Top-p。无法用于投机解码验证、语义缓存等需要完整候选集的下游任务；prefix-sum 的浮点非结合性还会导致非确定性。

统计截断法（Top-nσ, Min-p）

利用 logit 近似高斯分布做单遍统计切断，非常快但改变了采样输出，生成质量存在争议（Schaeffer 2025 指出 Min-p 存在夸大问题）。

枢轴选择法（RTop-k）

原为 GNN 节点选择设计的二分枢轴搜索。存在两大局限：(1) 仅适合 <1000 元素的小向量，词表 ≥6144 时甚至比 PyTorch 排序还慢；(2) 无重复值处理，遇到相同 logit 会陷入死循环 / 非确定性。

核心矛盾：在生产环境中，Top-k 和 Top-p 仍是主流方案（vLLM、SGLang 默认支持），但目前缺少一个同时具备高性能、严格语义、确定性的 GPU 实现。这就是 Qrita 要填补的空白。

三、相关工作与差距

vLLM 默认 排序 / RadixSelect ✅✅✅⚠️ 中

Qrita 相比现有算法有三大优势：

  1. 避免全词表排序，内存开销小，GPU 高性能。
  2. 返回完整的 Top-k / Top-p 候选集（而不是单个采样 token），兼容投机解码、语义缓存等下游任务。
  3. 保留严格的 Top-k / Top-p 语义与可复现性，不同于统计截断法。

四、核心算法设计

4.1 算法总体流程

1
高斯 σ 截断：单遍扫描粗筛掉噪声区（近似高斯分布的低概率 token），得到少量 outlier 集 Zt。
2
截断命中判断：如果 |Zt| > k（或概率和 > p），使用 Zt 作为搜索集；否则回退到完整词表 Z（保证语义正确）。
3
四元枢轴搜索：一次迭代评估 25% / 50% / 75% 三个 pivot，找到满足 Top-k / Top-p 的枢轴 τ，并同时跟踪最小超枢轴 logit 及其出现次数。
4
重复值处理：用累积和 + 掩码运算，精确保留恰好 k 个（或概率恰好 ≥ p 的）token，超出的重复值按原始位置顺序丢弃，实现确定性输出。

4.2 关键技术一：高斯 σ 截断（Gaussian σ-truncation）

观察：LLM 词表虽有 100K+，但每一步真正高概率的 token 通常 <100 个，剩余为近似高斯的噪声。

做法：抽样 logit 计算均值 μ 与标准差 σ，取截断阈值 t = μ + δ · σ。δ 由目标 k 或 p 通过预计算的查找表获得：

  • Top-k：δk = Φ-1(1 - k/V)（正态分位数函数）
  • Top-p：δp = Φp-1(p)（基于样本累积 softmax 概率）
  • 为保险留 0.2 × |t| 的安全余量，防止漏掉真正的 outlier。
效果：在实验中，Top-k=50 时截断后平均只剩 276~2368 个元素（远小于 128K~262K 词表），且命中率 100%，从根源上把搜索空间缩了 2 个数量级。

4.3 关键技术二：四元枢轴搜索（Quaternary Pivot Search）

传统 RTop-k 是二分搜索，Qrita 将其扩展为三 pivot 四分区（每次评估 25%、50%、75% 三个位置），单次迭代覆盖信息量翻倍，迭代次数减半。 

Algorithm 2  Quaternary Top-k Pivot Search
Input: 搜索集 Z_s, 目标 k
Output: τ, z_dup, N_dup

l ← min(Z_s), r ← max(Z_s)
while (l ≠ r) ∧ (i ≤ 20):
    for n in {1, 2, 3}:
        τ_n ← l + (n/4) × (r - l)          # 三个 pivot
        N_τn  ← |{ z_i | z_i > τ_n }|      # 超过 pivot 的元素数
        z_mn  ← min({ z_i | z_i > τ_n })   # 超过 pivot 中的最小 logit
        N_zmn ← |{ z_i | z_i = z_mn }|     # 该最小 logit 出现次数

        # 终止条件：τ_n 满足 k，并且扣除重复后又小于 k
        if (N_τn ≥ k) ∧ (N_τn - N_zmn < k):
            return τ_n, z_mn, N_zmn        # 找到含重复的边界

    # 若无 pivot 命中，收缩上下界
    r ← (N_τ1 < k)? τ_1 : (N_τ2 < k)? τ_2 : (N_τ3 < k)? τ_3 : r
    l ← (N_τ3 > k)? τ_3 : (N_τ2 > k)? τ_2 : (N_τ1 > k)? τ_1 : l

核心巧思

  • 终止条件 (Nτ ≥ k) ∧ (Nτ - Nzm < k) 恰好识别出「τ 之上元素数超 k、但扣掉最小重复层后又不够 k」的关键边界，避免了朴素条件 Nτ = k 遇到重复值时的死循环。
  • Top-p 用相同结构，但把计数换成累积概率 Sπ = Σ pi，终止条件相应变为 (Sπ ≥ p) ∧ (Sπ - Spm < p)。
  • 作者也尝试过更多 pivot（八元等），但寄存器压力抵消了迭代减少的收益，四元是最佳权衡。
  • 最多迭代 20 次即达 1/240 精度，足以覆盖 fp32 分辨率。

4.4 关键技术三：重复值处理（Duplication Handling）

枢轴搜索结束后可能出现「恰好在边界上有多个相同 logit，但只要保留其中一部分」的情况。Qrita 用并行位运算精确处理： 

Algorithm 3  Top-k Output with Duplication Handling
M_τ      = 1(Z > τ)                    # 基础掩码：所有超过枢轴的 logit
N_τ      = Σ M_τ
N_keep   = N_dup - (N_τ - k)           # 需要保留的重复值个数
M_zdup   = 1(Z = z_dup)                # 定位所有重复边界值
C_zdup   = cumsum(M_zdup) ∧ M_zdup     # 记录每个重复值是第几次出现
M_remv   = 1(C_zdup > N_keep)          # 标记要删掉的多余重复
M_final  = M_τ ∧ ¬M_remv               # 最终掩码
O        = Z + (1 - M_final) · (-∞)    # 应用掩码

通过 cumsum + 掩码并行确定每个重复值的出现顺序，始终保留出现更靠前的元素，从而跨批次、跨硬件完全确定与可复现。这解决了 RTop-k 和拒绝采样法都无法保证的确定性问题。

4.5 工程优化：分层 Triton Block Size Autotune

Qrita 的向量算子（min / max / cumsum / mask）作用于两种规模的向量：

  • 全词表向量（105 级别）
  • 截断后向量（102 ~ 103 级别）

使用同一 block size 会导致小向量 padding 浪费 / 大向量迭代过多。作者引入分层 block size，用 Triton Autotune 让编译器为大小向量分别选择最优 block，实测消融显示此项优化贡献 ~30% 延迟改善。

五、实验评估

5.1 实验设置

  • 硬件：NVIDIA H100（主）、RTX 4090（消费级）、AMD MI355X（跨平台）。
  • 模型（词表大小）：R1-Distill-Llama-8B (128256)、Qwen3-8B (151936)、GPT-OSS-20B (201088)、Gemma3-4B (262208)。
  • 数据：WikiText-2 生成的真实 logits。
  • 基线：PyTorch sort、vLLM 默认、FlashInfer、SGLang。

5.2 吞吐性能

  • H100：Qrita 在几乎所有配置下均领先，即使对比语义更弱的 FlashInfer / SGLang 仍有优势；吞吐随 batch 线性扩展至 128 后趋缓（受限于 132 SM 数）。
  • RTX 4090：相比基线最高 2× 吞吐，在内存带宽受限的消费级卡上优势更明显。
  • AMD MI355X：Qrita 依赖 Triton 具备跨平台能力，性能碾压 PyTorch / vLLM；FlashInfer / SGLang 因仅支持 CUDA 而不可用。

六、关键洞察与工程启示

洞察 1：LLM logits 的准高斯性质是可利用的物理先验

不是把统计截断当作最终答案（会改变语义），而是作为「精确算法的搜索空间预筛」，鱼与熊掌可以兼得。

洞察 2：确定性 ≠ 性能牺牲

基于 cumsum 掩码的重复值处理，仅增加 ~3.5% 开销，就把非确定性问题彻底解决。对投机解码、RL 训练、复现实验非常关键。

洞察 3：算法设计与硬件资源需平衡

更多 pivot 理论上迭代更少，但寄存器压力上升会抵消收益。四元是权衡出的甜点。

洞察 4：完整候选集接口的价值

FlashInfer / SGLang 为速度牺牲了接口通用性（只返回单 token），阻断了下游许多重要用例。Qrita 保住了接口。

洞察 5：Triton 的可移植性红利

使用 Triton 使 Qrita 天然可跑在 AMD GPU 上，而 FlashInfer / SGLang 的手写 CUDA 无法迁移，这是长期战略优势。

洞察 6：把算法真的推到生产

Qrita 不仅是学术工作，其三元版本已经成为 vLLM 主分支的默认采样器，说明工程可用性和易于集成。

七、局限性与未来方向

  • Batch 维度扩展性瓶颈：当前每 Triton Program 处理一个 batch，H100 上 batch > 132（SM 数）后线性扩展性下降。作者提出未来让单个 Program 处理多个 batch。
  • Top-p 命中率仍有波动：由于 softmax 对 outlier 高度敏感，Top-p 的高斯建模不如 Top-k 精准。作者建议引入 per-model profiling 建立定制 δ 表。
  • 额外 buffer：σ 截断需要词表大小的 buffer；虽然可用截断集大小（几千）代替全词表来进一步降低占用，但当前实现尚未优化。
  • Top-k 截断阈值仍偏保守：头空数百 logit 有优化空间，但作者认为对当前 GPU 而言收益有限，仅在多 batch 场景下值得进一步收紧。

八、总结

Qrita 的核心贡献可以概括为三点：

  1. 把面向小向量的 RTop-k 枢轴搜索成功扩展到 LLM 大词表场景，靠高斯 σ 截断缩小 100× 搜索空间。
  2. 提出四元枢轴搜索 + 重复值精确处理，同时兼顾迭代效率与严格确定性。
  3. 用 Triton 实现完整算法，跨 NVIDIA / AMD 平台可用，端到端集成 vLLM 后成为其默认采样器，达到 2× kernel 加速、1.41× 端到端加速、内存减半。

这篇论文的价值不仅在于一个更快的算子，更展示了一条「用统计先验降低搜索空间，然后用精确算法完成最后一步」的通用思路，对其它 LLM 推理阶段的算子设计（如注意力稀疏化、KV cache 选择、投机解码 draft 阶段）都有借鉴意义。特别对于处于 LLM Serving / 推理系统方向的团队，Qrita 是一个近乎「即插即用」的性能提升点，其思路也适合作为算子级优化的教科书案例。
